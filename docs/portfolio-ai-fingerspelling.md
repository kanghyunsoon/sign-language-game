# 지문자 31자모 인식 모델 개선 기록

지문자 모델의 핵심 문제는 모델 크기가 아니라 입력 표현과 평가 조건이었다. 2D 랜드마크가 잃는 깊이·손바닥 방향을 3D 피처로 복원하고, 데이터량이 많은 2D 헤드와 결합했다. 이후 실사용에서 발견한 손목 각도 문제를 회전 증강으로 다시 검증했다.

## 범위

- 담당 브랜치: `feature/khs-ai-fingerspelling-server`
- 대상: 한국어 지문자 31개 자모
- 입력: MediaPipe Hand Landmarker 21점의 `x·y·z`
- 출력: 자모별 확률과 후보 목록
- 배포: TFLite 듀얼 헤드 + Python WebSocket 서버
- 제품 경계: 최종 입력 확정은 프론트엔드 시간축 디코더가 담당

## 실험 요약

| 회차 | 가설 | 결과 | 판단 |
| --- | --- | --- | --- |
| T-150 | 2D에서 사라진 방향을 3D 피처로 복원 | v3 LSTM 93.3%, min recall 0.52 | 채택 |
| T-151 | v2 데이터량과 v3 표현력을 확률 평균으로 결합 | 98.68%, min recall 0.831 | 채택 |
| T-152 | 실사용 `ㅡ` 실패는 손목 각도 분포 문제 | 최종 98.42%, ±20°에서 `ㅡ` recall 1.00 | 채택 |
| rot2 | `ㅓ`를 margin으로 추가 보정 | 전체 96.68%, `ㅡ` recall 0.707 | 폐기 |

수치는 같은 조건끼리만 비교했다. T-150의 test 955개와 T-151 이후 1,900개는 구성 차이가 있어 정확도 차이를 단순 향상분으로 계산하지 않는다.

## 1. 2D 모델의 한계

### 증상

`ㅅ/ㅠ`, `ㅔ/ㅕ`, 손등 방향과 상하 반전처럼 2D 투영이 비슷한 자모가 섞였다. 초기 정적 이미지 기준선은 test 190개에서 66.84%였다. MLP, Residual MLP, SVM, pair-aware loss를 바꿔도 혼동쌍이 남았다.

### 진단

`feature_v2`는 20개 2D bone vector 40개와 관절 각도 15개로 구성된다. 손가락이 카메라 쪽으로 향하는지, 손바닥이 앞을 보는지 뒤를 보는지는 이 표현에서 사라진다. 분류기는 입력에 없는 정보를 복원할 수 없다.

### 조치

`feature_v3`를 78차원으로 설계했다.

| 구성 | 차원 | 역할 |
| --- | ---: | --- |
| 3D bone direction | 60 | 20개 뼈의 x·y·z 방향 |
| joint angle | 15 | 손가락 굽힘 관계 |
| palm normal | 3 | 손바닥 방향과 반전 구분 |

왼손은 x축을 mirror하고, bone vector는 손 크기로 정규화했다. 프론트는 이미 랜드마크의 z값을 보내고 있어 메시지 계약은 바꾸지 않았다.

### 결과

v3 LSTM은 동일 촬영 영상의 앞 70% 학습·뒤 30% 평가 조건에서 93.3%를 기록했다.

| 자모 | v2 전이 recall | v3 recall |
| --- | ---: | ---: |
| `ㅅ` | 0.42 | 1.00 |
| `ㅁ` | 0.70 | 1.00 |
| `ㅠ` | 0.59 | 1.00 |
| `ㅔ` | 0.53 | 0.97 |
| `ㅓ` | 0.75 | 0.97 |

## 2. 듀얼 헤드 앙상블

### 문제

v3의 방향 표현은 효과가 있었지만 학습 시퀀스가 2,404개였다. 기존 v2 계열은 세션 시퀀스 33,738개로 학습돼 `ㅕ·ㅗ·ㄹ` 등에서 더 강했다. stride를 2에서 1로 줄여 v3 시퀀스를 3,359→6,693개로 늘렸지만 인접 프레임이 복제될 뿐 정확도는 93.3→93.0%였다.

### 조치

같은 원본 프레임에서 두 피처를 동시에 추출했다.

```text
21 landmarks
  ├─ feature_v2 55 → LSTM head A ─┐
  └─ feature_v3 78 → LSTM head B ─┴─ probability average 0.5 → 31 classes
```

v2 헤드는 세션 시퀀스와 촬영 영상을 함께 학습하고, v3 헤드는 촬영 영상으로 학습했다. class prior를 사후 보정하는 방식은 같은 프레임을 본 두 모델의 결합이 아니어서 폐기했다.

### 결과

| 단계 | accuracy | min recall | recall 0.90 미만 |
| --- | ---: | ---: | ---: |
| v3 단독 | 93.3% | 0.52 | 9개 |
| 듀얼 헤드 | 98.1% | 0.708 | 2개 |
| hard-negative 1차 | 98.5% | 0.738 | 2개 |
| hard-negative 2차 | 98.68% | 0.831 | 2개 |

hard-negative 쌍은 혼동행렬에서 자동 산출했다. 1차 margin 0.35는 `ㅜ`를 고쳤지만 `ㅓ`를 밀어내는 현상을 만들었다. margin을 0.25로 낮춘 2차 모델을 채택했다.

## 3. 실사용 `ㅡ` 실패와 회전 증강

### 문제

T-151 배포 후 `ㅡ`가 거의 인식되지 않았다. locked test에서는 recall 1.00, confidence 0.995였기 때문에 임계값을 바꾸는 것으로 해결할 수 없었다.

### 진단

`ㅡ/ㅣ/ㅜ`는 회전 관계에 있다. 자모당 촬영 영상이 하나여서 학습과 test가 같은 손목 각도를 공유했다. test가 통과한 것은 실사용 조건을 포함했기 때문이 아니라, 조건 차이가 없었기 때문이다.

### 조치

- 학습 샘플 60%에 회전 증강
- v2의 2D bone vector: 화면 평면 ±22°
- v3의 3D direction·palm normal: z축 ±22°, y축 ±15°
- 평가 입력도 ±10°, ±20°로 회전해 별도 측정

### 결과

| test 회전 | 전체 accuracy | `ㅡ` recall |
| --- | ---: | ---: |
| −20° | 98.3% | 1.00 |
| −10° | 98.4% | 1.00 |
| +10° | 98.4% | 1.00 |
| +20° | 98.4% | 1.00 |

최종 locked test 정확도는 98.68→98.42%로 낮아졌다. 평균 0.26%p보다 실사용 실패 해결을 우선해 회전 증강 모델을 배포했다.

`ㅓ-ㅡ`, `ㅓ-ㅕ` margin을 추가한 후속 모델은 `ㅓ` recall을 0.705→0.754로 올렸지만 `ㅡ`를 1.00→0.707로 낮췄다. 전체 정확도도 96.68%로 후퇴해 폐기했다.

## 4. 모델 밖 검증

폐쇄형 31-class 분류기는 어떤 손을 넣어도 한 자모를 고른다. 전체 confidence threshold를 올리면 오답뿐 아니라 원래 confidence가 낮은 정답 자모도 막힌다.

그래서 모델 출력 외에 다음 검증을 뒀다.

- top1과 top2의 확률 차이를 보는 decision margin gate
- `ㅎ/ㅂ`처럼 엄지 정보가 피처에서 약해지는 자모의 기하 handshape gate
- 자모별 precision·확정률을 기준으로 경쟁 출제 여부를 관리하는 `readiness.json`
- 여러 프레임의 투표와 안정 시간을 보는 프론트엔드 시간축 decoder

decision margin 0.25는 locked test에서 정답 95.7%를 유지하면서 오답 73.3%를 차단했다. 게이트는 argmax 라벨을 지우지 않고 confidence만 0.05로 낮춰 사용자에게 후보 피드백은 남긴다.

## 5. 배포 계약

운영 번들은 `jamo31-v2big.tflite`와 `jamo31-v3.tflite` 두 파일이다. LSTM을 unroll해 Flex 연산 의존을 제거했고 Keras 원본과의 max difference는 각각 `1.0e-07`, `9.3e-09`였다.

서버는 카메라 영상이 아니라 21개 랜드마크만 받는다. 응답은 prediction과 top candidates이며, 게임 입력 확정·잠금·해제는 프론트엔드가 맡는다. 모델을 교체해도 WebSocket session과 게임 규칙을 바꾸지 않도록 `ModelRunner` 인터페이스와 manifest에서 label 순서·shape·hash를 검증한다.

## 6. 남은 과제

- 최종 98.42%는 신규 사용자 독립 평가가 아니다.
- `ㅓ` recall 0.7049와 `ㅡ` precision 0.8356의 충돌이 남아 있다.
- 새 사용자·손목 각도·가림·조명 조건을 분리한 final test가 필요하다.
- 기하 handshape gate의 임계값은 랜드마크 데이터로 재보정해야 한다.
- 실시간 p50/p95 지연과 분당 오확정은 코드에서 수집하지만 결과를 저장하지 않아 미측정이다.

평가의 원본 기록은 [`model-evaluation.md`](../ai/game-server/docs/recognition/model-evaluation.md), 운영 수치는 [`manifest.json`](../ai/models/jamo-31-ensemble-v1/manifest.json), 게임 출제 기준은 [`readiness.json`](../ai/contracts/recognition/readiness.json)에 있다.
