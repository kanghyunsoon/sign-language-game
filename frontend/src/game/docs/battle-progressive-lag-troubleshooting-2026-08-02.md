# 프링글수 게임 진행 중 누적 렉 트러블슈팅 — 2026-08-02

## 증상

- 1:1 게임을 오래 진행할수록 프레임이 점차 떨어지고 입력·물리·상대 보드 표시가 함께 느려졌다.
- 새 글자가 추가될 때마다 브라우저의 DOM, Pixi 장면 그래프, GPU 합성 레이어, 동기화 순회 비용이 계속 증가했다.
- 짧은 게임에서는 문제가 잘 드러나지 않았지만 글자가 누적된 장시간 게임에서 플레이가 어려워졌다.

## 원인

1. 솔로·1:1 화면은 DOM 마스크 글자를 실제 화면에 표시하지만, 같은 글자마다 보이지 않는 Pixi `LetterView`도 만들고 있었다. `LetterView` 하나가 여러 Pixi 객체를 소유하므로 글자 수에 비례해 장면 그래프와 GPU 메모리가 불필요하게 증가했다.
2. 모든 DOM 글자에 영구적인 `will-change`가 적용되어 정착한 글자도 각각 GPU 합성 레이어를 계속 점유했다.
3. 움직임이 없는 정착 보드도 매 화면 프레임마다 Matter 상태 조회, DOM 렌더 비교, 네트워크 발행 판단을 수행했다. 상대 보드도 같은 방식으로 매 프레임 전체 글자를 순회했다.
4. 상대 보드의 제거 이력과 P2P 명령 처리 이력이 게임이 끝날 때까지 상한 없이 증가했다.
5. 로컬 보드 발행기가 매 갱신마다 임시 배열과 `Set`을 새로 만들어 장시간 게임에서 가비지 컬렉션 부담을 키웠다.

## 적용한 해결

### 렌더 객체와 GPU 레이어

- `showScenery: false`인 DOM 렌더 모드에서는 보이지 않는 Pixi `LetterView`를 생성하지 않는다.
- 제거 효과는 Pixi 뷰가 없는 DOM 글자에서도 완료 이벤트를 정상 발생시키되, 보이지 않는 Pixi 파티클은 만들지 않는다.
- 낙하 중인 글자만 `will-change: transform`을 사용한다. 정착 즉시 `will-change: auto`로 되돌려 합성 레이어를 반환한다.
- DOM 글자에 `contain: layout style paint`를 적용해 글자 갱신이 게임판 밖의 레이아웃·페인트로 전파되지 않게 했다.

### 적응형 프레임 주기

- 로컬 보드에 낙하 글자나 제거 효과가 있으면 기존 프레임 주기로 갱신한다.
- 완전히 정착한 로컬 보드는 100ms 간격(10FPS)으로 상태 조회·렌더·발행 판단을 제한한다.
- 상대 보드는 이동 중 30FPS, 정착 후 10FPS로 전체 순회를 제한한다.
- 카메라 랜드마크 표시는 20FPS로 제한하고 인식·AI 전송의 latest-only 정책은 유지한다.

### 누적 상태 상한과 할당 감소

- 상대 보드의 제거 tombstone은 최근 128개만 보존한다.
- P2P 중복 명령 방지 ID는 최근 256개만 보존한다.
- 정착 ID 집합은 실제 구성에 변화가 있을 때만 재구성하고 매 프레임 배열·집합 생성을 피한다.

## 캐시 정책

모든 캐시를 주기적으로 비우는 방식은 사용하지 않는다. 글자 마스크·윤곽 캐시는 제한된 지문자 집합을 재사용하므로 비우면 래스터 재생성과 순간 프레임 저하가 반복된다. 대신 실제로 상한 없이 증가하던 이력만 제한하고, 재사용 가치가 있는 정적 캐시는 유지한다.

## 회귀 검증

- 정착 보드 60프레임을 연속 호출하는 테스트에서 전체 물리·렌더 순회가 약 10회로 제한되는지 검증한다.
- 제거 tombstone 128개 상한과 최신 제거 ID의 재등장 방지를 검증한다.
- 게임 물리·상대 보드·P2P 전송·글자 래스터 대상 51개 테스트가 통과했다.
- Vite 프로덕션 빌드가 통과했다.
- 전체 Vitest는 833개 중 824개가 통과했다. 기존 메뉴 접근성 기대값 7개와 인식 세션 2개는 이번 성능 변경과 무관한 기존 실패로 별도 정리가 필요하다.

## 장시간 수동 점검

1. 서로 다른 두 브라우저로 1:1 게임에 입장한다.
2. 각 보드에 글자를 최소 15개 이상 누적하고 10분 이상 플레이한다.
3. Chrome DevTools Performance Monitor에서 JS heap, DOM node, GPU memory가 입력 횟수와 함께 무제한 증가하지 않는지 확인한다.
4. 정착 상태에서 CPU 사용률이 내려가고 새 글자가 생성되면 즉시 부드러운 프레임으로 복귀하는지 확인한다.
5. 상대 보드의 낙하·제거·망치 전송이 누락되거나 10FPS로 고정되지 않는지 확인한다.
6. 재대결과 방 나가기를 반복한 뒤 이전 게임의 DOM 글자, rAF, P2P 명령 이력이 남지 않는지 확인한다.

## 2026-08-03 후속: 상대 보드 부드러움·뒤로가기 클릭 범위

### 증상

- 장시간 누적 비용을 줄인 뒤에도 상대 낙하 글자는 전송 패킷 사이에서 끊겨 보일 수 있었다.
- 솔로와 1:1 플레이 헤더의 타이틀 이미지 투명 영역이 뒤로가기 원형 버튼 일부를 덮어,
  보이는 범위보다 실제 클릭 범위가 작았다.

### 조치

- 이동 중인 글자 변환은 30Hz로 전송하고 상대 보드는 낙하 중 60Hz로 샘플링한다.
  정착 보드는 기존 저비용 갱신 주기를 유지한다.
- 주기 전체 스냅샷은 5초 간격으로 낮추되, 정착·제거·구조 변경에서는 즉시 권위 스냅샷을 전송한다.
- `RemoteTransformBuffer`가 마지막 FALLING 변환을 최대 70ms까지만 제한적으로 예측해
  짧은 패킷 공백을 메운다. 권위 상태와 멀어지는 장시간 예측은 허용하지 않는다.
- 솔로·1:1의 뒤로가기 버튼을 타이틀 이미지보다 위 레이어로 올리고 타이틀 이미지는 포인터
  이벤트를 받지 않도록 해, 보이는 원형 전체를 클릭할 수 있게 했다.

### 검증

- `RemoteTransformBuffer`, `RemoteBoardReplica`, `LocalBoardPublisher` 집중 테스트 21건 통과.
- `npm.cmd run build` 통과.
