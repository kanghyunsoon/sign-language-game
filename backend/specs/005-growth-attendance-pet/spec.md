## User Scenarios & Testing *(mandatory)*

### User Story 1 - 하루 출석을 기록하고 연속 출석을 확인한다 (Priority: P1)

로그인한 사용자는 하루에 한 번 출석하고, 출석 직후 오늘의 출석 완료 여부와 현재 연속 출석 일수를 확인한다. 시스템은 사용자가 같은 날짜에 여러 번 출석하더라도 출석 기록과 보상을 한 번만 인정한다.

**Why this priority**: 출석은 사용자가 성장 기능에 매일 진입하는 시작점이며, 출석 보상과 연속 이용 동기를 함께 제공한다.

**Independent Test**: 출석 이력이 없는 사용자, 전날 출석한 사용자, 하루 이상 빠진 사용자가 각각 출석한 뒤 오늘의 출석 상태와 연속 출석 일수가 올바른지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 오늘 출석하지 않은 로그인 사용자, **When** 출석을 완료하면, **Then** 오늘 출석이 기록되고 연속 출석 일수와 출석 보상이 한 번 반영된다.
2. **Given** 전날까지 빠짐없이 출석한 사용자, **When** 오늘 출석하면, **Then** 연속 출석 일수가 전날보다 1 증가한다.
3. **Given** 전날 출석하지 않은 사용자, **When** 오늘 출석하면, **Then** 연속 출석 일수가 1로 다시 시작한다.
4. **Given** 오늘 이미 출석한 사용자, **When** 다시 출석을 시도하면, **Then** 새 출석이나 추가 보상 없이 이미 출석했다는 결과와 현재 연속 출석 일수가 제공된다.
5. **Given** 오늘 출석하지 않은 사용자가 거의 동시에 여러 번 출석을 시도한 상황, **When** 요청들이 처리되면, **Then** 출석 기록과 보상은 각각 정확히 한 번만 반영된다.

**User Flow**:

1. 사용자가 로그인한 상태로 성장 화면에 진입한다.
2. 시스템이 오늘의 출석 여부, 현재 연속 출석 일수와 펫 상태를 보여준다.
3. 아직 출석하지 않았다면 사용자가 출석을 선택한다.
4. 시스템이 오늘 출석 기록의 존재 여부를 확인한다.
5. 첫 출석이면 오늘 기록을 만들고, 전날 기록을 기준으로 연속 출석 일수를 계산한다.
6. 출석 보상을 펫 성장에 한 번 반영하고 필요한 경우 레벨을 갱신한다.
7. 사용자는 갱신된 출석 상태, 연속 출석 일수와 펫 성장 결과를 확인한다.

### User Story 2 - 활동 보상으로 펫을 성장시킨다 (Priority: P1)

로그인한 사용자는 출석, 기준 점수 이상의 테스트 완료, 솔로 게임 기록 달성 또는 1대1 게임 정상 종료처럼 인정된 활동을 마치면 펫 경험치를 얻는다. 연습에는 경험치를 지급하지 않으며 백엔드는 연습 세션이나 시작·완료 API를 제공하지 않는다. 솔로 게임의 `score`는 게임 진행 시간(초)을 뜻하며, 정상 완료된 매 게임에서 60초 이하는 경험치 15, 60초 초과 90초 이하는 10, 90초 초과 120초 이하는 5를 지급하고 120초를 초과하면 지급하지 않는다. 1대1 게임은 승자에게 총 10, 패자에게 3을 지급한다. 프로토타입에서는 레벨마다 20 경험치가 필요하고, 펫은 5·10·15·20레벨에 자동으로 진화하여 총 5단계를 거친다. 최대 레벨인 20레벨 이후에는 경험치가 더 이상 증가하지 않는다. 동일한 활동 결과가 다시 전달되어도 보상은 중복 지급되지 않는다. 솔로 게임의 시작 기호 목록, 글자별 통계와 시작·완료 세션 상태는 게임에서 관리하며, 백엔드가 신뢰하는 별도 게임 서버가 완료 결과를 유일하게 전송한다. 백엔드는 이 서버에서 받은 `score`만 솔로 결과로 처리한다.

**Why this priority**: 활동과 펫 성장을 연결하는 것이 지속적인 학습과 게임 참여를 유도하는 핵심 가치다.

**Independent Test**: 출석, 테스트 점수, 초 단위 솔로 `score`와 1대1 승패 결과를 경계값별로 반영한 뒤 활동별 경험치가 정확히 한 번 지급되고 레벨 및 진화 단계가 기준과 일치하는지 확인하며, 연습 완료로는 경험치가 변하지 않는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 오늘 처음 출석한 사용자, **When** 출석이 정상적으로 완료되면, **Then** 경험치 3이 펫에 정확히 한 번 추가된다.
2. **Given** 연습 모드 한 회차를 정상적으로 완료한 사용자, **When** 펫 상태를 확인하면, **Then** 연습으로 인한 경험치는 추가되지 않고 백엔드에 연습 세션도 생성되지 않는다.
3. **Given** 테스트 모드를 완료하고 정답률이 80% 이상인 사용자, **When** 완료 결과가 인정되면, **Then** 경험치 7이 정확히 한 번 추가된다.
4. **Given** 테스트 모드를 완료했지만 정답률이 80% 미만인 사용자, **When** 완료 결과가 처리되면, **Then** 테스트 경험치는 지급되지 않는다.
5. **Given** 솔로 모드 완료 결과의 `score`가 60 이하인 사용자, **When** 결과가 확정되면, **Then** 경험치 15가 지급된다.
6. **Given** 솔로 모드 완료 결과의 `score`가 60 초과 90 이하인 사용자, **When** 결과가 확정되면, **Then** 경험치 10이 지급된다.
7. **Given** 솔로 모드 완료 결과의 `score`가 90 초과 120 이하인 사용자, **When** 결과가 확정되면, **Then** 경험치 5가 지급된다.
8. **Given** 솔로 모드 완료 결과의 `score`가 120을 초과한 사용자, **When** 결과가 확정되면, **Then** 솔로 경험치는 지급되지 않는다.
9. **Given** 1대1 게임의 승자로 확정된 사용자, **When** 게임 결과가 정상적으로 인정되면, **Then** 경험치 10이 정확히 한 번 추가된다.
10. **Given** 1대1 게임의 패자로 확정됐지만 경기를 정상 종료한 사용자, **When** 게임 결과가 정상적으로 인정되면, **Then** 경험치 3이 정확히 한 번 추가된다.
11. **Given** 이미 보상받은 출석·테스트·게임 결과, **When** 동일 결과가 다시 전달되면, **Then** 경험치와 레벨은 추가로 변경되지 않는다.
12. **Given** 현재 경험치와 새 보상의 합이 20 이상인 펫, **When** 보상이 반영되면, **Then** 20 경험치마다 레벨이 1 상승하고 초과 경험치는 다음 레벨 진행도에 남는다.
13. **Given** 보상 반영으로 5·10·15·20레벨 중 하나에 도달한 펫, **When** 레벨 상승이 완료되면, **Then** 해당 레벨의 진화 단계가 자동으로 적용된다.
14. **Given** 한 번의 보상으로 두 단계 이상의 레벨 기준을 충족한 펫, **When** 보상이 반영되면, **Then** 충족한 모든 레벨 상승이 누락 없이 적용된다.
15. **Given** 무효 처리되거나 정상 종료되지 않은 게임의 사용자, **When** 결과 처리가 끝나면, **Then** 게임 경험치는 지급되지 않는다.
16. **Given** 활동 완료와 보상 반영 중 일부 처리가 실패한 상황, **When** 사용자가 상태를 다시 확인하면, **Then** 활동 하나에 대해 보상이 누락되거나 중복된 부분 상태가 남지 않는다.
17. **Given** 19레벨 펫이 보상으로 20레벨에 도달하면서 경험치가 남는 상황, **When** 레벨 상승이 완료되면, **Then** 펫은 20레벨 최종 진화 상태가 되고 초과 경험치는 남지 않는다.
18. **Given** 이미 20레벨 최종 진화 상태인 펫, **When** 보상 조건을 충족하는 활동을 완료하면, **Then** 레벨과 경험치는 변경되지 않고 최대 성장 상태가 유지된다.
19. **Given** 기존 체계에서 10레벨이었던 펫, **When** 새 성장 체계가 적용되면, **Then** 기존 레벨과 경험치는 유지되고 진화 단계는 3단계로 재계산되며 20레벨까지 경험치를 다시 획득할 수 있다.
20. **Given** 솔로 게임이 완료된 사용자, **When** 결과가 저장되면, **Then** 백엔드는 게임 진행 시간(초)을 나타내는 `score`만 결과로 저장하고 별도 `duration_ms`, 시작 기호 목록과 글자별 통계는 저장하지 않는다.
21. **Given** 솔로 게임이 중단되거나 게임에서 재시작된 사용자, **When** 백엔드 상태를 확인하면, **Then** 미완료 솔로 세션은 저장되지 않으며 완료되어 제출된 결과만 존재한다.
22. **Given** 솔로 게임이 정상 완료된 사용자, **When** 신뢰하는 별도 게임 서버가 유일한 완료 결과를 전송하면, **Then** 백엔드는 해당 결과 요약과 보상을 처리하며 사용자 클라이언트나 신뢰하지 않는 주체가 직접 보낸 결과는 처리하지 않는다.
23. **Given** 사용자별 솔로 결과가 하나 이상 저장되어 있을 때, **When** 솔로 랭킹을 조회하면, **Then** 각 사용자의 최소 `score`를 기준으로 낮은 점수부터 정렬되고 최소 점수가 같은 사용자는 같은 순위를 받는다.
24. **Given** 대전과 솔로 결과가 함께 존재할 때, **When** 결과의 의미를 해석하면, **Then** `game_type`이 솔로이면 `score`는 게임 진행 시간(초), 대전이면 승리 1·패배 0을 뜻한다.

**User Flow**:

1. 사용자가 출석, 테스트 또는 게임 활동을 수행한다.
2. 해당 기능이 활동의 완료 여부와 보상 자격을 확정한다.
3. 성장 기능이 활동 종류와 고유한 완료 결과를 확인한다.
4. 테스트는 정답률, 솔로 게임은 최종 `score`, 1대1 게임은 승패 결과로 보상 자격과 경험치를 결정한다.
5. 아직 보상하지 않은 적격 활동이면 해당 활동의 경험치를 펫에 반영한다.
6. 경험치 20마다 최대 20레벨까지 레벨을 올리고, 5·10·15·20레벨에 도달하면 진화 단계를 갱신한다.
7. 동일 활동이 이미 보상되었다면 현재 상태를 유지한다.
8. 사용자는 갱신된 레벨, 경험치와 진화 단계를 확인하며, 20레벨이면 다음 성장 목표 대신 최대 성장 상태임을 확인한다.

### User Story 3 - 펫의 레벨과 진화 상태를 확인한다 (Priority: P2)

로그인한 사용자는 자신에게 고정된 하나의 펫에 대해 현재 진화 단계, 레벨, 경험치와 다음 레벨까지 필요한 경험치를 한 화면에서 확인한다. 펫은 별도의 이름을 갖지 않으며, 사용자가 선택하거나 교체하지 않아도 레벨 구간에 따라 자동으로 진화한다.

**Why this priority**: 사용자가 활동 보상의 결과와 다음 성장 목표를 이해해야 성장 기능이 지속적인 이용 동기로 작동한다.

**Independent Test**: 펫을 가진 사용자가 상태를 조회했을 때 현재 진화 단계, 레벨, 현재 경험치, 다음 레벨 기준과 남은 경험치가 프로토타입 성장 기준과 일치하는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 가입과 함께 펫이 생성된 로그인 사용자, **When** 펫 상태를 확인하면, **Then** 현재 진화 단계, 레벨, 현재 경험치, 다음 레벨 기준과 남은 경험치가 표시된다.
2. **Given** 방금 출석·테스트 완료·게임 승리 보상을 받은 사용자, **When** 펫 상태를 다시 확인하면, **Then** 최신 경험치와 레벨이 표시된다.
3. **Given** 아직 성장 보상을 받은 적이 없는 신규 사용자, **When** 펫 상태를 확인하면, **Then** 초기 레벨과 초기 경험치가 표시된다.
4. **Given** 인증되지 않았거나 탈퇴 처리된 사용자, **When** 펫 상태 확인을 시도하면, **Then** 다른 사용자의 펫 정보가 노출되지 않고 접근이 거부된다.
5. **Given** 경험치 반영으로 펫의 레벨이 진화 기준에 도달한 사용자, **When** 펫 상태를 확인하면, **Then** 해당 레벨에 맞는 새로운 진화 단계가 자동으로 표시된다.
6. **Given** 펫이 20레벨에 도달한 사용자, **When** 펫 상태를 확인하면, **Then** 최종 진화 단계와 최대 레벨 도달 상태가 표시되고 다음 레벨 기준은 표시되지 않는다.

**User Flow**:

1. 사용자가 로그인 후 성장 화면에 진입한다.
2. 시스템이 로그인 사용자에게 연결된 단 하나의 펫을 찾는다.
3. 시스템이 현재 레벨에 해당하는 진화 단계, 현재 경험치와 다음 성장 목표를 보여준다.
4. 사용자는 추가 선택 없이 자신의 현재 성장 상태와 다음 목표를 이해한다.

### Edge Cases

- 서비스가 사용하는 날짜 경계 직전에 출석 요청이 시작되어 경계 직후 완료되더라도 하나의 기준 날짜로만 판정되어야 한다.
- 같은 사용자의 출석 요청이 동시에 처리되어도 같은 날짜의 출석과 보상은 각각 하나만 남아야 한다.
- 테스트 완료 또는 1대1 게임 결과가 재전송되거나 순서가 뒤바뀌어 도착해도 같은 활동의 보상은 한 번만 지급되어야 한다.
- 신뢰 게임 서버는 동일한 솔로 완료 결과를 백엔드에 두 번 이상 전송하지 않아야 한다.
- 존재하지 않거나 다른 사용자에게 속한 활동 결과로 보상을 요청하면 보상이 지급되지 않아야 한다.
- 펫이 생성되지 않은 비정상 계정은 임의의 기본 펫을 보여주지 않고 복구 가능한 오류로 안내되어야 한다.
- 경험치가 정확히 레벨 기준과 같아지는 경우에도 레벨 상승이 적용되어야 한다.
- 한 번의 경험치 증가로 여러 레벨 기준을 넘으면 가능한 레벨 상승을 모두 적용해야 한다.
- 테스트 정답률이 정확히 80%이면 경험치 7을 지급해야 한다.
- 솔로 `score`가 정확히 60, 90 또는 120이면 각각 경험치 15, 10 또는 5를 지급해야 한다.
- 20레벨에 도달하는 보상에 초과 경험치가 포함되어도 레벨은 20을 넘지 않고 초과분은 남지 않아야 한다.
- 20레벨 사용자가 적격 활동을 반복해도 레벨과 경험치가 변경되지 않아야 한다.
- 기존 체계의 10레벨 펫은 새 체계 적용 후 레벨과 경험치를 유지하고 3단계로 재분류되어야 하며, 20레벨까지 다시 성장할 수 있어야 한다.
- 활동 결과는 확정됐지만 보상 반영이 일시적으로 완료되지 못한 경우, 재처리해도 보상이 중복되지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 인증된 사용자가 서비스 기준 날짜마다 한 번 출석할 수 있도록 해야 한다.
- **FR-002**: 시스템은 사용자와 기준 날짜의 조합으로 출석의 유일성을 보장해야 한다.
- **FR-003**: 시스템은 사용자의 가장 최근 출석이 기준 날짜의 바로 전날이면 연속 출석 일수를 1 증가시켜야 한다.
- **FR-004**: 시스템은 바로 전날 출석이 없으면 새 출석의 연속 출석 일수를 1로 설정해야 한다.
- **FR-005**: 시스템은 이미 출석한 날짜의 재시도에 대해 추가 기록과 추가 보상을 만들지 않고 현재 출석 결과를 제공해야 한다.
- **FR-006**: 시스템은 출석 완료 후 갱신된 연속 출석 일수와 펫 성장 결과를 사용자가 확인할 수 있게 해야 한다.
- **FR-007**: 시스템은 첫 출석에 경험치 3을 지급해야 한다.
- **FR-008**: 시스템은 동일한 출석, 테스트 또는 1대1 게임 결과에 대한 경험치를 정확히 한 번만 지급해야 한다.
- **FR-009**: 시스템은 무효이거나 정상 종료되지 않은 게임 결과에 경험치를 지급하지 않아야 한다.
- **FR-010**: 시스템은 테스트 정답률이 80% 이상이면 경험치 7을 지급하고, 80% 미만이거나 완료되지 않은 테스트에는 지급하지 않아야 한다.
- **FR-011**: 시스템은 현재 경험치가 20에 도달할 때마다 최대 20레벨까지 레벨을 1 올리고, 20레벨 미만에서 20을 초과한 경험치는 다음 레벨 진행도로 이월해야 한다.
- **FR-012**: 시스템은 활동 완료 판정, 경험치 지급과 레벨 변경 사이에 사용자에게 모순되는 부분 상태가 남지 않도록 해야 한다.
- **FR-013**: 시스템은 로그인 사용자의 단일 펫에 대해서만 성장 정보를 제공해야 한다.
- **FR-014**: 사용자는 자신의 펫 진화 단계, 현재 레벨과 현재 경험치를 확인할 수 있어야 하며, 20레벨 미만에서는 다음 레벨 기준과 남은 경험치, 20레벨에서는 최대 성장 상태를 확인할 수 있어야 한다.
- **FR-015**: 시스템은 성장 활동 직후 조회에서 최신 펫 상태를 제공해야 한다.
- **FR-016**: 시스템은 인증되지 않은 사용자, 탈퇴한 사용자 또는 다른 사용자의 펫·활동 정보에 대한 접근을 거부해야 한다.
- **FR-017**: 시스템은 동일 사용자에 대한 동시 출석 또는 동시 활동 결과 처리에서도 출석과 경험치가 중복되지 않도록 해야 한다.
- **FR-018**: 프로토타입의 경험치 보상값, 레벨당 필요 경험치 20, 진화 레벨 5·10·15·20과 최대 레벨 20은 모든 사용자에게 일관되게 적용되어야 하며 정책 변경이 기존 완료 활동을 자동으로 다시 보상해서는 안 된다.
- **FR-019**: 시스템은 사용자가 자신의 오늘 출석 여부와 현재 연속 출석 일수를 확인할 수 있도록 해야 한다.
- **FR-020**: 시스템은 펫이 누락된 비정상 계정을 정상 계정처럼 표시하지 않고 사용자에게 복구 가능한 오류를 제공해야 한다.
- **FR-021**: 시스템은 사용자마다 이름과 선택 절차가 없는 하나의 펫만 유지해야 한다.
- **FR-022**: 시스템은 펫의 진화 단계를 레벨 1~4에서 1단계, 5~9에서 2단계, 10~14에서 3단계, 15~19에서 4단계, 20에서 최종 5단계로 자동 전환해야 한다.
- **FR-023**: 시스템은 솔로 모드의 초 단위 `score`가 60 이하이면 경험치 15, 60 초과 90 이하이면 10, 90 초과 120 이하이면 5를 지급하고, 120을 초과하면 지급하지 않아야 한다.
- **FR-024**: 시스템은 정상 종료된 1대1 게임의 승자에게 총 경험치 10, 패자에게 경험치 3을 지급해야 한다.
- **FR-025**: 시스템은 펫이 20레벨에 도달할 때 남는 초과 경험치를 버리고 현재 경험치를 0으로 설정하며, 이후 활동에는 경험치를 추가하지 않아야 한다.
- **FR-026**: 프로토타입에서는 출석을 제외한 서로 다른 유효 활동 완료마다 보상을 지급 횟수 제한 없이 적용하되, 동일 완료 결과의 중복 지급은 금지해야 한다. 솔로 결과의 유일성과 중복 전송 방지는 신뢰 게임 서버가 보장해야 한다.
- **FR-027**: 새 성장 체계 적용 시 시스템은 기존 펫의 레벨과 경험치를 유지하고 새 레벨 구간에 따라 진화 단계를 재계산해야 하며, 기존 10레벨 펫에도 20레벨까지 적격 활동 경험치를 다시 지급해야 한다.
- **FR-028**: 시스템은 솔로 결과에서 게임 진행 시간(초)을 나타내는 `score`만 저장해야 하며, 별도 `duration_ms`, 시작 기호 목록과 글자별 정답·오답·확정 통계는 저장하지 않아야 한다.
- **FR-029**: 시스템은 솔로 게임의 시작·진행·중단·재시작 상태를 저장하지 않고, 게임에서 제출한 완료 결과만 처리해야 한다.
- **FR-030**: 시스템은 백엔드가 신뢰하는 별도 게임 서버가 보낸 솔로 완료 결과만 처리해야 하며, 솔로 결과의 유일성과 중복 전송 방지는 해당 게임 서버의 책임으로 두어야 한다.
- **FR-031**: 시스템은 연습 완료에 경험치를 지급하지 않아야 하며, `practice_sessions` 테이블과 연습 시작·완료 API를 제공하지 않아야 한다.
- **FR-032**: 시스템은 솔로 랭킹을 사용자별 최소 `score`의 오름차순으로 산정하고, 최소 점수가 같은 사용자에게 같은 순위를 부여해야 한다.
- **FR-033**: 시스템은 `game_type`에 따라 `score`를 해석해야 한다. 솔로 `score`는 게임 진행 시간(초)을 뜻하고 낮을수록 좋은 기록이며, 대전 `score`는 승리 1·패배 0을 뜻한다.

### Key Entities

- **사용자**: 인증된 서비스 이용자이며 하나의 펫, 날짜별 출석 기록과 보상 대상 활동의 주체다.
- **출석 기록**: 사용자가 특정 기준 날짜에 출석했다는 사실과 그 시점의 연속 출석 일수를 나타내며, 한 사용자에게 날짜별 하나만 존재한다.
- **사용자 펫**: 사용자에게 하나만 고정되는 이름 없는 성장 대상이며 현재 레벨과 경험치를 가진다. 현재 진화 단계는 레벨 구간에 따라 결정된다.
- **보상 대상 활동**: 출석, 80% 이상 정답을 맞힌 테스트, 최종 `score` 구간을 충족한 솔로 완료 또는 정상 종료된 1대1 승패처럼 경험치 지급 자격을 만드는 완료 결과다. 각 결과는 동일 활동을 구분할 수 있는 고유한 정체성을 가진다.
- **성장 정책**: 활동 종류와 성과별 경험치, 레벨당 필요 경험치 20, 5·10·15·20레벨의 진화 기준과 최대 레벨 20을 정의하는 프로토타입 규칙이다.

### Out of Scope

- 펫에 이름을 붙이거나 변경하는 기능
- 사용자가 여러 펫 중 하나를 선택하거나 펫을 교체하는 기능
- 사용자가 진화 대상을 선택하거나 진화를 수동으로 실행하는 기능
- 펫 외형 변경, 아이템, 먹이 주기, 상점과 같은 육성 부가 기능
- 사용자에게 경험치 지급 이력 전체를 조회시키는 기능
- 솔로 게임의 시작 기호 목록과 글자별 정답·오답·확정 통계를 백엔드에 저장하거나 조회하는 기능
- 솔로 게임의 시작·진행·중단·재시작 세션 상태를 백엔드에 저장하거나 복구하는 기능
- 신뢰 게임 서버가 전송한 솔로 완료 결과를 백엔드에서 별도로 중복 판정하는 기능
- 연습 완료 경험치, 연습 세션 이력 저장과 연습 시작·완료 API
- 테스트 정답 판정이나 게임 승패 판정 자체
- 운영자가 성장 정책을 화면에서 편집하는 기능
- 정책 변경 후 과거 활동을 소급하여 재계산하거나 재보상하는 기능
- 20레벨을 초과하는 레벨, 경험치 누적 또는 추가 진화 단계

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 정상적인 환경에서 출석 시작 후 5초 이내에 출석 완료 여부, 연속 출석 일수와 갱신된 펫 상태를 확인할 수 있다.
- **SC-002**: 동일 사용자의 같은 날짜 출석이 반복되거나 동시에 요청된 모든 검증 사례에서 출석 기록과 출석 보상은 각각 정확히 한 번만 반영된다.
- **SC-003**: 출석, 테스트 점수와 1대1 결과의 반복·재전송 검증 사례 100%에서 적격 활동 하나당 정해진 보상이 정확히 한 번 지급되며, 신뢰 게임 서버의 솔로 결과 전송 검증 사례 100%에서 동일 완료 결과가 두 번 이상 전송되지 않는다.
- **SC-004**: 경험치 20 경계, 다중 레벨 상승, 5·10·15·20레벨 진화와 최대 레벨 초과 방지 검증 사례 100%에서 최종 레벨, 경험치와 진화 단계가 예상 결과와 일치한다.
- **SC-005**: 사용자의 95% 이상이 성장 화면 진입 후 2초 이내에 펫의 진화 단계, 현재 상태와 다음 레벨까지 남은 경험치를 확인할 수 있다.
- **SC-006**: 신규 사용자, 활동 이력이 있는 사용자와 최고 경계 경험치 사용자를 포함한 검증 사례 100%에서 자신의 펫 정보만 조회된다.
- **SC-007**: 사용자 검증에서 90% 이상이 별도 설명 없이 현재 펫 상태와 다음 성장 목표를 한 번의 조회로 정확히 이해한다.
- **SC-008**: 솔로 결과가 여러 건이거나 동점자가 포함된 랭킹 검증 사례 100%에서 사용자별 최소 `score`, 오름차순 순서와 공동 순위가 예상 결과와 일치한다.

## Assumptions

- 날짜별 출석은 서비스의 주 사용자 지역에 맞춘 대한민국 표준시의 달력 날짜를 기준으로 한다.
- 사용자는 기존 인증 절차를 통해 식별되며 가입이 완료될 때 이름 없는 하나의 초기 펫이 생성되고 이후 선택이나 교체 없이 유지된다.
- 펫의 진화 단계는 현재 레벨 구간만으로 결정되며, 진화 조건을 충족하면 사용자 선택 없이 자동으로 변경된다.
- 테스트 및 1대1 게임 기능은 완료 여부, 점수, 승패와 결과의 고유성을 신뢰할 수 있는 형태로 확정해 성장 기능에 전달한다.
- 솔로 게임의 시작 기호 목록과 글자별 통계는 게임에서 관리하며 백엔드의 결과 저장·보상·랭킹에는 사용하지 않는다.
- 솔로 게임 중단과 재시작은 게임에서 관리하며 백엔드는 미완료 솔로 세션을 추적하지 않는다.
- 솔로 완료 결과는 백엔드가 신뢰하는 별도 게임 서버만 전달하며, 해당 서버가 결과의 유일성과 중복 전송 방지를 보장한다.
- 솔로 `score`는 게임 진행 시간(초)을 뜻하므로 낮을수록 더 좋은 성과이며, 랭킹에는 사용자별 최소 점수만 사용한다.
- 프로토타입에서는 출석 3, 테스트 정답률 80% 이상 7, 솔로 `score`가 60 이하일 때 15·60 초과 90 이하일 때 10·90 초과 120 이하일 때 5, 1대1 승리 10·패배 3의 경험치를 사용하며 연습에는 경험치를 지급하지 않는다.
- 레벨마다 경험치 20이 필요하며 레벨 상승 후 초과 경험치는 다음 레벨 진행도로 이월한다.
- 20레벨 도달 시 남은 초과 경험치는 버리고 현재 경험치는 0으로 표시하며, 이후 적격 활동에도 경험치를 추가하지 않는다.
- 새 성장 체계 적용 시 기존 펫의 레벨과 경험치는 유지하며 진화 단계만 새 레벨 구간에 따라 재계산한다. 따라서 기존 10레벨 펫은 3단계가 되고 20레벨까지 경험치를 다시 획득한다.
- 출석은 하루 한 번만 보상하고, 테스트·게임은 서로 다른 유효 완료 결과마다 별도의 일일 횟수 제한 없이 보상한다.
- 출석, 기준을 충족한 테스트와 게임 결과 이외의 활동은 프로토타입에서 경험치를 지급하지 않는다.
- 사용자에게는 현재 성장 상태만 제공하며, 개별 경험치 지급 이력은 첫 번째 범위에서 제공하지 않는다.
- Jira의 `USER-01-01`, `USER-01-02`, `TEST-01-03`, `GAME-02-08` 범위가 이 기능보다 먼저 사용 가능한 상태라고 가정한다.
